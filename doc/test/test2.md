# test2：循环内局部函数调用的优化机会

## 用例与目的

源码位于 [test/m/test2/test2.m](../../test/m/test2/test2.m)：

```matlab
function x = test2(b)
    x = 1;
    for i = 1:b
        x = innerFunction(x);
    end
end

function x = innerFunction(x)
    x = 1+x;
end
```

这个用例用于观察局部函数解析、循环中的调用与类型分派、槽位提升、函数内联以及范围遍历的优化。本文描述后续机会，不表示这些优化已经实现。

## 当前生成结果

配置好 README 中的运行时依赖后，在项目根目录执行：

```bash
./build/baltam_ir test/m/test2/test2.m -o /tmp/test2.ir
./build/opt -passes=mem2reg /tmp/test2.ir -o /tmp/test2.ssa.ir
```

当前生成与读取均成功。运行 mem2reg 后，两个函数仍保持 Non-SSA，主要原因是：

- 外层的 `colon` 和 `apply innerFunction(...)` 都具有 `MayWriteSlot` 效果，触发整函数跳过。
- 内层的 `plus` 同样被保守标记为 `MayWriteSlot`。
- 外层 x 是返回槽位；内层 x 同时是参数和返回槽位。即使解除上述屏障，当前 mem2reg 也不会提升这些槽位。

外层 IR 目前先生成范围和遍历状态，再使用内部索引槽位 `slot_for.index.bb1` 遍历。循环体读取元素并写入 `slot_i`，随后通过 `apply innerFunction` 更新 `slot_x`。这说明当前调用仍保留名字歧义，并没有自动变成静态调用。

## 1. 解析调用目标

`innerFunction` 是同文件局部函数，是确定调用目标的候选。后续名字解析应结合词法可见性、变量绑定和类方法分派规则，将能够证明的调用从 ApplyInst 转成 CallInst，并记录同模块函数目标。

静态绑定可以减少每次迭代的函数查找。如果仍需运行时分派，则可以使用调用点缓存：按既定世界计数与入参分类规则复用目标。世界或类型变化时仍按缓存设计检查，不能仅因为名字出现在同一个文件就跳过所有分派规则。

调用目标确定后，还需要效果分析，才能决定哪些槽位读写可以穿越调用。调用缓存本身不会消除传参、工作区建立和返回交付的开销。

## 2. 精细化效果分析

普通局部函数拥有独立工作区。内层对自身 x 的赋值，不等于隐式修改调用者的工作区。可以通过函数效果摘要区分自身局部写入、调用者或捕获变量写入、全局与持久状态写入，以及其他副作用和异常。

对已经确认使用内置数值语义的加法，也可以证明它不会改写工作区。当前所有二元运算统一标记为 MayWriteSlot，会阻止此类安全优化。

这需要同时处理重载和动态调用：只有在目标与语义得到证明时才能缩小效果集合。不能把“不会写 slot”进一步等同于“可以删除或任意移动”，因为运算仍可能抛错或产生其他可观察行为。

## 3. 提升循环变量与返回值计算

解除效果屏障后，循环内部索引有机会由现有 mem2reg 提升。x 的提升则需要扩展返回槽位策略：可以将循环中的当前 x 保存在 SSA 值中，仅在返回前写回返回槽位，沿用无操作数 ret 的返回约定。

预期值关系如下，省略遍历细节，符号名称仅为示意：

```text
entry:
    %initial = const 1
    goto header
header:
    %x = phi [entry, %initial], [body, %next]
    ...
    branch %condition, body, exit
body:
    %next = call innerFunction(%x)
    goto header
exit:
    store slot_x %x
    ret
```

入口值和循环回边值通过 PHI 汇合。循环执行零次时，出口使用初始值 1。多个返回路径需要各自在正确位置交付当前结果，不能只更新阶段标签或直接删除返回槽位。

## 4. 内联小函数

在调用目标、分派约束和函数效果明确后，可以内联 innerFunction，将调用替换为一次加法：

```text
%next = plus %one, %x
```

这样可以消除函数调用、参数工作区初始化和返回值交付的开销。内联需要映射内层参数、局部值和返回槽位，保留错误及副作用顺序；不能机械地拼接两个函数的 SlotId。

内联后可继续消除重复常量和无用槽位读写。模块常量元数据共享同一个标签，只表示数据去重，不表示已经合并了每条 ConstInst 的运行时物化。

## 5. 类型传播与数值特化

在确认初始常量和加法使用内置语义后，x 从 double 标量开始，每次加法仍得到 double 标量。这为循环内的类型传播和直接数值运算提供了依据，可以避免每轮重新进行加法分派。

这种结论依赖加法目标及环境假设。采用运行时特化时，需要入口守卫以及假设失效时的回退策略；调用目标缓存不能替代这些检查。

## 6. 范围遍历与无用变量

源码没有读取 i，可以考虑删除对 slot_i 的写入。只有在证明获取迭代元素没有可观察副作用或异常后，才能继续删除对应的 foreach_get。

若确认 `1:b` 使用内置数值冒号语义，还可以采用范围描述或计数循环，避免创建完整的数值数组。当前生成的范围、遍历状态和索引操作为后续识别提供了结构。

b 的类型及形状目前未知。对类对象或其他重载语义，范围构造和取元素可能有不同的可观察行为，不能直接用整数循环代替。

## 语义边界与验证

不能一般性地把整个函数改成 `x = 1+b`。需要保留空范围、非整数边界、范围构造错误以及逐次浮点加法的舍入行为。即使已知循环次数，也不能未经证明将顺序累加替换为一次加法。

后续验证至少覆盖：

- 内置普通数值边界，包括零次、一次、多次迭代及非整数边界。
- 范围构造失败或发生重载的输入。
- 调用分派假设变化时的重新解析或回退。
- 优化前后返回值、异常及副作用顺序一致。
- Non-SSA 源版本保留，克隆后的 Value/Use 关系和循环 PHI 输入正确。

建议先完善解析与效果分析，再扩展返回槽位提升和内联，最后接入类型特化、无用计算清理与范围优化。具体分析和变换基础见 [mem2reg 设计](../../docs/mem2reg设计.md) 与 [函数调用点缓存设计](../../docs/函数调用点缓存设计.md)。
