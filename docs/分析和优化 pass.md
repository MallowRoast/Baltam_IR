# 分析和优化 pass

## Non-SSA 阶段

AST 降低完成、IR 结构检查通过后，对 Non-SSA IR 单独运行优化 pass。IRBuilder 保留源码的求值顺序和显式 slot 读写；优化在已构建的 IR 上进行。建议先简化控制流，再消除冗余 slot 读写，最后清理不再使用的常量指令；若控制流简化或读写消除又暴露新的机会，可重复相关 pass，直到没有变化或达到迭代上限。

### 1. SlotLoadStoreElimination

减少重复 `LoadSlotInst` 和无用 `StoreSlotInst`，保留 `SlotTable` 及 slot 的运行时语义，不要求将 slot 提升为 SSA 值。

- 在基本块内跟踪各 slot 的已知值。已有值可用时，用该 `ValueId` 替换后续 load 的结果，并删除该 load；删除前须同步更新该版本的 `ValueTable` 和所有使用点。
- `StoreSlotInst` 更新其目标 slot 的已知值。若前一次 store 在被读取或观察前被覆盖，且删除不会改变可见行为，可以删除前一次 store。函数输出、全局变量、持久变量、嵌套函数共享的工作区和异常路径都可能使写入可被观察，判定不足时保留 store。
- `Instruction::effect()` 的 `NoSlotWrite` 不使已知 slot 值失效；`MayWriteSlot` 表示可能写入。已知目标时按目标更新或失效；写入范围未知时保守地使相关记录失效。该枚举只描述 slot 写入，不证明指令可删除或可重排。
- 首版仅处理基本块内可证明安全的情况。跨基本块传播需要控制流数据流分析，合流处只有各前驱一致的事实才能继续使用。

### 2. 控制流简化

删除不可达块，折叠目标相同的条件分支，合并可安全合并的直线基本块，并消除只负责跳转的中转块。变换后更新入口、跳转目标及 `ValueTable` 中指向被删除指令的定义；保留条件求值及其可能的副作用。对常量条件的分支折叠，须先确认其真假转换语义。

### 3. 多余常量指令移除

删除结果没有使用者的 `ConstInst`。删除前检查该结果是否被返回、传给其他指令或用于需要保留的运行时状态；删除时同步清理 `ValueTable` 的定义记录。此 pass 只清理无用常量，不承担常量折叠或普通指令的死代码删除。

## 实现边界

上述是计划中的 pass，当前尚未实现。现有 `ValueTable` 用连续 `ValueId` 索引 `std::vector<ValueInfo>`，只提供追加和值查询；删除指令前须先设计不使其他编号失效的值表更新方式，并维护所有使用点。每个 pass 应明确自身修改的 IR 结构和需要维护的引用关系；修改完成后运行独立的 IR 检查。涉及异常、动态分派或工作区可观察性的情况，先采用保守规则。
