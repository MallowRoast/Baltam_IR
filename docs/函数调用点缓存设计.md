# 函数调用点缓存设计

## 1. 目标与范围

在调用点保存上一次成功分派的目标，避免参数类型和解析环境稳定时重复执行函数查找、类方法选择等操作。

本文为目标设计，当前尚未实现 `CallCache` 和执行器接入。第一版采用单目标缓存：每个调用点仅保存最近一次的目标和全部入参类型，不预设多类型组合缓存。

缓存用于 `CallInst` 的运行时分派。`ApplyInst` 中变量取值与按名字调用的歧义，需要先由执行器处理；函数句柄调用由 `ValueApplyInst` 处理，不直接套用本文规则。同模块已静态绑定的局部函数和嵌套函数，可直接使用现有目标，不必再次执行名字分派；嵌套函数需要的执行环境仍从当前执行帧取得。

## 2. 设计前提

本方案采用以下分派约定：

- 普通函数分派只受 `path` 影响，不受函数参数影响。函数内部的类型判断和参数检查仍正常执行，不由缓存省略。
- 类方法分派除受 `path` 影响外，还受到函数参数的影响，因此类参数发生变化时需要重新解析。
- 调用点的函数名和词法解析上下文固定；搜索路径、当前目录等可变解析环境由全局世界计数反映。
- 同一调用点不会在全局世界未变化的情况下，被多个不同的解析环境共用；若以后支持这种执行模式，应按环境隔离缓存或增加环境身份检查。

本方案假定具体内置类型不影响普通函数及类方法的目标选择。若将来引入针对不同内置类型、形状或具体数值的目标重载，必须细化分派标识和复用规则，否则不能继续直接命中。

## 3. 缓存内容

示意结构如下，类型名称表示职责，不代表当前已有接口：

```cpp
struct CallCache {
    bool valid = false;
    WorldId world = 0;
    std::vector<TypeId> argument_types;
    ResolvedTarget target;
};
```

| 字段 | 含义 |
| --- | --- |
| `valid` | 是否保存了一份成功解析的结果 |
| `world` | 该结果最近在哪个全局世界完成解析 |
| `argument_types` | 上一次成功调用目标选择所对应的全部入参类型，保留数量和顺序 |
| `target` | 已解析目标，能够判断它是普通函数还是类方法，并保证目标存活 |

`valid` 为 true 只表示存在缓存结果，不能替代世界检查；世界变化后，即使它暂时仍为 true，也不能命中。

普通函数和类方法是目标的语义类别。静态类方法仍属于类方法，不能归入普通函数。目标自身应提供类别信息，避免另设一个可能与目标不一致的布尔字段。

### 3.1 入参类型

每个参数使用一个整数分派标识：所有内置类型统一记录为 `Builtin`，不区分 double、single、整数、逻辑等具体内置类型；类对象记录具体类的身份，不能只记录通用的“类对象”类别。`TypeId` 在本文中表示这个分派标识，而不是对象的完整运行时类型。

```text
(Builtin, Builtin)
(ClassA, Builtin)
(ClassB, Builtin)
```

以上是不同的分派标识列表。`foo(double)` 和 `foo(single)` 都记录为 `(Builtin)`；`foo(ClassA, double)` 和 `foo(ClassA, single)` 都记录为 `(ClassA, Builtin)`，均可视为类型一致。参数数量和顺序仍属于列表的一部分。不同对象实例如果具有同一类身份，可以命中同一条缓存；不比较实例地址和普通属性值。

类重新加载或身份编号复用时，必须推进世界计数。统一整数编码可保留一个值表示 `Builtin`，其余值用于区分类身份。整个列表的哈希值不能单独作为类型相等的证明。

## 4. 与世界计数和 IR 缓存的关系

`IRModule` 表示某份源码对应的 IR，不持有运行时世界计数，也不因搜索路径变化而失效。

现有文件缓存与调用点缓存可以读取同一个 `WorldCounter`，但各自保存独立的检查记录：

| 状态 | 记录的内容 | 检查对象 |
| --- | --- | --- |
| `CacheEntry::world` | 最近完成源文件有效性检查的世界 | 已知源码文件及其缓存模块 |
| `CallCache::world` | 最近成功完成调用目标解析的世界 | 本调用点的分派结果 |

文件缓存检查通过，不代表该模块中的调用目标已得到验证。某个调用点更新自己的世界，也不能替其他调用点完成验证。

现有 `CacheEntry` 在同一世界复用上次检查结果，跨世界才重新检查文件修改时间；文件未变时继续使用原模块。这只是降低文件系统检查频率，不负责函数分派验证。

更新 `CallCache::world` 是记录本次解析所对应的全局世界值，不调用 `WorldCounter::advance()`。全局世界由实际改变解析环境的操作，或约定的外部变化检查边界推进。

## 5. 命中与重新解析规则

本节的“入参类型相同”指参数数量、顺序及分派标识一致，不要求具体内置类型相同。

| 缓存状态 | 世界是否相同 | 入参类型是否相同 | 新参数有无类对象 | 上次目标 | 行为 |
| --- | --- | --- | --- | --- | --- |
| 无效 | / | / | / | / | 重新解析 |
| 有效 | 不同 | / | / | / | 清除有效标志，重新解析 |
| 有效 | 相同 | 相同 | / | / | 直接复用 |
| 有效 | 相同 | 不同 | 无 | 普通函数 | 复用目标，更新入参类型 |
| 有效 | 相同 | 不同 | 有 | / | 重新解析 |
| 有效 | 相同 | 不同 | 无 | 类方法 | 重新解析 |

核心流程：

```text
缓存无效，或缓存世界与当前全局世界不同
    → 将 valid 置为 false
    → 重新解析目标

否则，所有入参类型与缓存相同
    → 复用目标

否则，旧目标是普通函数，且新入参没有类对象
    → 复用目标
    → 更新缓存中的全部入参类型

否则
    → 将 valid 置为 false
    → 重新解析目标
```

### 5.1 重新解析

重新解析期间保持 `valid == false`。成功后完成以下步骤：

1. 取得新的目标及目标类别，并建立保证目标存活的句柄。
2. 记录本次全部入参类型。
3. 记录这次解析结果所对应的世界。
4. 最后将 `valid` 置为 true。

解析失败时不恢复旧的有效标志，不能退回旧目标继续调用。缓存命中只省略目标解析，不能跳过调用本身的参数检查和执行错误处理。

第一阶段按单线程执行设计。若解析过程本身可能加载插件、类或函数并改变世界，应在稳定的世界下确认结果；不能把旧世界得到的目标直接标记为新世界有效。可在检测到世界变化后重新解析，或由解析器明确返回结果对应的世界。

### 5.2 典型情况

```text
上次：foo(double) → 普通函数 F
本次：foo(single)，世界未变
结果：两次均记录为 (Builtin)，直接命中并复用 F，无需更新类型列表。

上次：foo(ClassA) → 类方法 A.foo
本次：foo(ClassA)，世界未变
结果：类型相同，复用 A.foo。

上次：foo(ClassA) → 类方法 A.foo
本次：foo(ClassB)，世界未变
结果：存在类参数且类型变化，重新解析。

上次：foo(ClassA) → 类方法 A.foo
本次：foo(double)，世界未变
结果：上次为类方法，即使本次无类参数也重新解析。
```

## 6. 世界推进与失效来源

以下变化可能影响目标选择，必须在后续调用检查之前推进世界或明确使相关缓存失效：

- 当前目录或搜索路径改变，例如 `cd`、`addpath`、`rmpath`。
- 函数被清除、替换或重新加载。
- 类定义、方法集合、继承关系或分派优先关系改变。
- 插件函数注册、替换或卸载。
- 在约定的执行边界观察到外部文件新增、删除或修改。

世界计数不会自动感知文件系统变化。外部修改何时可见，取决于运行时约定的检查边界；不要求在每次调用点命中时检查目标文件时间戳。

若被调用函数在执行中改变了解析环境，后续调用点也必须观察到世界变化，不能只在最外层执行开始时检查。

## 7. 目标生命周期与持久化

动态目标不能仅以裸 `FunctionUnit*` 保活。目标句柄需要持有所属模块或其他拥有者；插件目标需要保证关联动态库不会在使用期间卸载。已有执行帧仍在使用的旧目标，可以按执行语义继续存活；缓存替换不应破坏它。

调用点缓存属于进程内运行状态，不写入 IR 持久化文件。从 IR 文件读取、复制生成新的执行实例时，缓存从无效状态开始。持久化的调用分派声明与静态函数路径，不等同于本次运行解析出的缓存目标。

缓存逻辑上属于调用点，具体可以由调用节点持有，也可以放入执行器按指令索引管理的状态表。存放位置不改变本文的命中规则；后续多线程或多解析环境执行时，需要相应隔离或同步。

## 8. 开销与启用策略

第一版为需要运行时分派的调用点启用单目标缓存，不仅限于循环体。循环之外的调用也可能因递归或函数被反复执行而成为热点。

快路径尽量只执行以下操作：

1. 检查 `valid` 和世界计数。
2. 比较参数数量及分派标识；内置参数只判断是否为内置类型，类参数比较具体类身份。
3. 命中时直接取得目标句柄并调用。

类型不一致时再使用“普通函数且没有类对象”的规则。可以在同一次参数遍历中完成类型比较和类对象检测，避免重复扫描；复用类型列表容量，避免每次命中都构造临时数组或分配内存。

缓存的实际收益需要测量。若一次性调用较多导致空间或初始化开销明显，可考虑第二次执行才分配缓存，或按执行次数启用，而不是仅按是否位于循环体决定。多类型组合缓存留待后续根据实际命中率引入。
