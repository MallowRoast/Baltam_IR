# IR 生成正确性测试方案

## 1. 目标与当前范围

验证从 M 源码生成的 IR 是否正确，并为后续 SSA 转换、优化和持久化提供持续回归依据。测试需要分别回答三个问题：结构是否合法、是否表达了预期源码语义、写出和读取后是否保持一致。

当前仅保留 `test/syntax` 语法样例，独立 C++ 测试程序、CTest 注册和辅助脚本均已移除。样例可通过命令行工具手动运行，尚无统一自动验证入口。

本方案为后续实施设计，不新增独立 C++ 测试程序或 CMake 辅助脚本。后续统一验证入口应复用现有样例。

## 2. 第一层：所有生成结果都经过结构校验

设计统一的 `verify_ir(module)`，在测试构建中对每次完整生成的模块执行，在读取 IR 后也执行。校验器只检查 IR 约束，不通过重新调用 builder 来判断正确性。

| 检查范围 | 必须满足的约束 |
| --- | --- |
| 所有权 | 模块、代码单元、基本块和指令之间的父指针及所属关系一致 |
| 函数与槽位 | 函数索引无歧义，签名和指令使用的槽位存在，嵌套关系无环 |
| 基本块 | 标签唯一，入口块属于当前版本，跳转目标属于同一代码单元的当前版本 |
| 终结指令 | 完整生成后的块具有合法终结指令，终结指令后没有其他指令 |
| 值引用 | 结果编号不重复，所有输入引用已定义的值，引用不跨代码单元或阶段版本 |
| 值表 | 每条结果与值表双向对应，定义指针、结果序号和值形态匹配，特别检查多结果调用 |
| 指令约束 | 操作数数量和指令种类一致，元胞元素数量与构造形状一致，必需指针非空 |
| 调用 | 静态目标属于本模块；已绑定目标与声明的分派类别兼容 |
| 常量 | 对象非空，类型和完整形状有效，不能使用打印摘要代替真实数据验证 |

可达路径上的临时值使用应满足定义先于使用及跨块支配关系；Non-SSA 中槽位可重复写入，不要求槽位满足 SSA。不可达块单独检查结构，不简单地因为没有前驱就拒绝。现阶段只验证已支持的 IR 约束，不把尚未实现的 SSA/PHI 能力算作已覆盖。

将来支持 PHI 后，增加 PHI 前驱对应、类型和值引用规则，并按实际阶段检查 SSA 约束。不能依靠是否存在 PHI 推断模块或函数阶段。

校验失败至少报告源码路径、函数、基本块、指令位置和具体原因，避免只返回 false。

## 3. 第二层：小样例验证精确的 lowering 语义

每个样例尽量只覆盖一个明确行为，人工确定预期的指令关系和控制流。继续使用现有测试程序进行结构断言，减少仅按指令数量判断的用例。

重点覆盖：

| 类别 | 关键断言 |
| --- | --- |
| 常量 | 实际类型、完整形状和元素数据正确；浮点特殊值保留位模式 |
| 表达式 | 运算种类、操作数绑定和求值顺序正确，不能只数二元指令数量 |
| 赋值 | RHS 求值与槽位存储顺序正确，多次写入保持源码顺序 |
| 调用与索引 | Apply、Call、ValueApply 与索引节点选择正确；多输出顺序及结果序号正确 |
| 短路逻辑 | RHS 仅能从应当求值的分支到达，不能被无条件提前计算 |
| if/elseif/else | 条件、分支目标、合流和无 else 路径正确 |
| switch | case 匹配顺序和默认分支正确，不产生错误的 case 穿透 |
| for/while | 初始化、条件、循环体、更新和退出边正确；检查零次迭代路径 |
| break/continue | 跳转到最近一层循环的正确退出块或继续块，检查嵌套循环 |
| return | 终止当前单元，不能让后续语句继续可达；返回顺序正确 |
| 脚本与函数 | 脚本主体、局部函数、多层嵌套函数的归属、签名和静态目标正确 |
| 点号与容器 | 静态/动态字段、圆括号/花括号读写和删除节点正确，参数顺序不丢失 |

断言应尽量通过前驱、后继、指令类型和值关系定位对象，不依赖固定的 `bb7` 或 `%12`。只有明确要求编号规则的检查才固定编号。

可以为少量有代表性的样例保留人工审核的 IR 文本基线，便于查看整体变化；不要求每个样例维护一份完整文本。基线不能由当前实现运行后未经审核直接当作正确答案，更新时必须解释语义变化。

## 4. 第三层：持久化一致性

对语法样例执行完整链路：

```text
M 源码 → IR_A → 写出 IR 和 MAT → 读取 IR_B
                    ↓                 ↓
                结构校验          结构校验
                    └────比较语义结构────┘
```

比较内容包括：

- 模块代码单元、当前函数阶段、槽位名称与签名。
- 指令种类、操作数顺序、控制流边和多结果值表。
- 嵌套函数关系、调用分派信息及静态目标的模块内身份。
- 常量类型、完整形状和真实元素数据；浮点逐位比较，容器递归比较。
- 同一常量标签是否在读取后共享只读对象。

内存地址不能作为跨模块比较依据，函数目标按模块内路径匹配。MAT 资源目录会随输出文件名变化，比较时只归一化这类输出位置，不隐藏类型、数值、控制流和目标变化。

补充检查：重复读写、资源目录整体移动、相对路径、字符串转义、空数组、多维数组，以及 9/10 元素内联与 MAT 的边界。

往返一致只证明读写没有改变结果，不能代替第二层语义检查：错误 IR 也可能被原样保存和恢复。

## 5. 第四层：执行结果与副作用对照

当前新 IR 执行器尚未实现，这一层作为后续验收要求，不作为当前已完成能力。

执行器具备基础功能后，对同一输入分别运行参考实现和 IR 执行，比较返回值、可观察副作用及错误行为。参考实现可使用已确认语义的现有解释器；对存在语义差异的部分使用人工定义的独立预期结果。

结果比较需要明确数值容差，不能把所有计算结果都要求逐位一致；常量编解码的逐位检查仍单独保留。NaN、无穷、复数、类型和形状分别处理。

用于验证求值顺序的样例，应通过计数或事件序列观察调用副作用，例如条件不成立时 RHS 调用次数必须为零。仅比较最终数值可能漏掉重复调用或错误的提前求值。

后续每个优化 pass 均采用：输入 IR 校验 → 执行 pass → 输出 IR 校验 → 优化前后执行对照。性能提升不能代替语义一致性。

## 6. 错误输入与校验器自身验证

从合法的小模块中单独破坏一个约束，确认校验器拒绝：

- 未定义值、重复结果、越界槽位和不属于当前函数的跳转目标。
- 终结指令后继续添加指令、错误的多结果索引、悬空静态调用目标。
- 缺失或重复元数据标签、类型/形状冲突、浮点位宽错误。
- MAT 文件缺失、变量 value 缺失、数据类型或形状不匹配。

同时保留合法的空数组、不可达块等边界用例，避免校验器错误拒绝合法 IR。错误诊断使用中文并包含位置。

## 7. 运行策略

每次修改 lowering、IR 数据结构或持久化代码时，执行：

1. 在 `build` 中配置并构建，通过命令行运行相关语法样例。
2. 统一校验入口接入后，对现有语法样例运行结构校验和对应语义断言。
3. 对涉及读写的修改运行持久化比较。
4. 每次修复一个生成错误，补充一个最小回归样例。

```bash
cmake -S . -B build
cmake --build build
./build/baltam_ir test/syntax/if_else.m -o /tmp/if_else.ir
./build/opt -passes=mem2reg /tmp/if_else.ir -o /tmp/if_else.ssa.ir
```

以上命令仅用于构建及手动运行样例。统一验证入口、校验器和完整比较需要按本文后续接入；不能因为命令退出成功，就声称所有设计层次均已实现。CI 使用兼容且固定的 SDK，初始化失败应报告为环境错误，不能跳过后算作通过。

开发构建中可默认启用生成后校验；发布构建通过开关控制，避免把完整图检查的开销放到每次生产执行中。

## 8. 实施顺序与验收

建议按以下顺序落地：

1. 实现统一结构校验器，接入统一的语法样例测试入口，完善错误定位。
2. 为关键语法样例增加值关系、控制流和求值顺序断言。
3. 在同一测试入口加入模块语义结构与常量数据的持久化比较，不增加分散的测试程序。
4. 执行器可用后接入行为对照；优化 pass 可用后增加优化前后比较。

当前阶段的合格条件是：所有支持语法样例通过结构校验和对应语义断言，读写比较通过，错误 IR 能被拒绝，所有已修复缺陷有回归样例。新增语法必须同时增加独立的预期行为检查。

这套方案不能以有限样例证明任意程序正确，但能让结构错误自动暴露，并为每种已支持语义提供可审查、可重复运行的证据。
