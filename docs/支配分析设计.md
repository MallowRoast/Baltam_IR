# 支配分析设计

## 1. 范围与输入

支配分析基于单个 `IRStageVersion` 的 CFG，提供直接支配节点、支配树、支配关系查询和支配边界，为 mem2reg 的 PHI 放置及变量重命名服务。接口和实现位于 `src/Analysis/ir_analysis.h/.cpp`，已提供 `CFGAnalysis` 和 `DominatorAnalysis`。

当前控制流边由基本块末尾的 `GotoInst`、`BranchInst` 表达，返回指令没有后继。`CFGAnalysis` 已统一提供入口、块索引、去重后的前驱和后继；`DominatorAnalysis` 只读取该视图，不再扫描指令。

Analysis 和 Transform 假定输入 IR 已满足结构约束，不负责验证空块、块归属、重复身份、入口、终结指令或跳转目标。相关检查由后续专门的 Verifier Pass 统一承担。支配分析要求入口无前驱；需要跳回原入口时先增加独立入口。空版本返回空 CFG 和空支配结果。查询索引及块指针的有效性由调用方保证。

CFG 保存所有块；支配分析只对入口可达块计算支配信息。不可达块无直接支配节点，不加入支配树及边界；支配分析使用前驱集合时忽略来自不可达块的边。同一前驱到后继的重复边只计一次。

## 2. 分析结果

使用一个 `DominatorAnalysis` 同时保存直接支配、支配树和支配边界，避免三份结果重复维护块身份与所有权。支配分析对外使用 CFG 的紧凑块索引查询；从基本块指针查询时，先调用 `cfg.index(block)`。

接口以 `CFGAnalysis::BlockIndex` 查询结果，提供 `reachable`、`immediate_dominator`、`dominates`、`children` 和 `frontier`。构造方式如下：

```cpp
CFGAnalysis cfg(*function.current_version());
DominatorAnalysis dominators(cfg);
```

CFG 不拥有基本块，调用方保证阶段版本存活；支配分析仅保存块索引及结果，不持有 CFG 引用。控制流改变后两者均需重建。支配分析对不可达块返回无直接支配节点、空子节点和空边界，支配查询返回 false。

### 2.1 CFGAnalysis 接口

`BlockIndex` 为 `std::size_t`，按 `version.blocks()` 的存储顺序从零分配，不解析块标签，也不表示 RPO。

| 接口 | 返回内容 |
| --- | --- |
| `entry()` | 入口块指针，空 CFG 返回 `nullptr` |
| `size()` | 包括不可达块在内的块数量 |
| `index(block)` | 块指针对应的索引，调用方保证块属于当前 CFG |
| `block(index)` | 索引对应的基本块指针 |
| `predecessors(index)` | 去重后的前驱索引列表 |
| `successors(index)` | 去重后的后继索引列表 |

构造分两轮：先收集全部块并建立索引，再扫描终结指令建立双向邻接关系。Goto 产生一条边，Branch 按真、假目标顺序产生边，相同目标只保留一次，Return 没有后继。前驱按源块索引顺序收集。

### 2.2 DominatorAnalysis 接口

| 接口 | 返回内容 |
| --- | --- |
| `reachable(index)` | 是否从入口可达 |
| `immediate_dominator(index)` | `std::optional<BlockIndex>`，入口和不可达块返回 `std::nullopt` |
| `children(index)` | 支配树子节点索引列表，按块索引排序 |
| `frontier(index)` | 支配边界索引列表，排序且去重 |
| `dominates(a, b)` | 可达块 a 是否支配可达块 b，包含支配自身 |

分析查询不检查索引范围或块归属，这些是调用方的接口前提。不可达块的子节点和边界为空，涉及不可达块的支配查询返回 false。

使用示例：

```cpp
#include "Analysis/ir_analysis.h"

CFGAnalysis cfg(*function.current_version());
DominatorAnalysis dominators(cfg);
const auto index = cfg.index(block);
const auto parent = dominators.immediate_dominator(index);
for (const auto boundary : dominators.frontier(index)) {
    const BasicBlock* target = cfg.block(boundary);
    // 后续 mem2reg 根据具体 slot 的定义块决定是否在 target 放置 PHI。
}
```

### 2.3 内部数据

主要数据与保存范围：

| 数据 | 用途及保存范围 |
| --- | --- |
| 逆后序块列表、RPO 序号及内部 idom 数组 | 构造期间计算，完成后释放 |
| 每个块的 reachable 和可选 idom | 长期保存，可区分入口与不可达块 |
| 每个块的 children | 支配树子节点 |
| 每个块的 frontier | 去重后的支配边界 |
| 支配树 DFS 进入和退出序号 | 常数时间支配查询 |

第一版一次计算完整结果，不引入增量维护或分析管理框架。树子节点、边界输出采用稳定块顺序，便于调试和测试。

## 3. 直接支配节点

如果从入口到 B 的所有路径都经过 A，则 A 支配 B。每个可达块支配自身。B 的直接支配节点是距离 B 最近的严格支配节点。

采用基于 CFG 逆后序的迭代算法，优先保证实现简洁，不在第一版引入复杂的近线性算法。

1. 从入口使用显式栈 DFS 得到后序，反转为逆后序 RPO，入口的 RPO 序号为 0。
2. 内部暂设 `idom(entry) = entry`，其他块未确定。
3. 按 RPO 遍历非入口块，对已经得到 idom 的可达前驱求共同支配祖先。
4. 若得到的新 idom 不同则更新，重复扫描直到没有变化。
5. 对外查询入口的直接支配节点返回 `std::nullopt`；内部自指仅用于求解，不作为树边。

两个已确定块 A、B 的祖先求交：

```text
while A != B:
    while rpo(A) > rpo(B):
        A = idom(A)
    while rpo(B) > rpo(A):
        B = idom(B)
return A
```

一个块的所有可达前驱最终都必须参与求交；未确定前驱只能在当前轮暂时跳过，不能永久忽略。算法遍历的是 CFG 的 RPO，不是基本块存储顺序，也不是块名中的编号。

## 4. 支配树和查询

直接支配关系稳定后，对每个非入口可达块 B 执行：

```text
children[idom(B)].push_back(B)
```

入口为树根。沿支配树使用显式栈 DFS，记录每个节点的进入和退出序号。对于可达块：

```text
dominates(A, B) = enter(A) <= enter(B) && exit(B) <= exit(A)
```

不可达块不参与该判断，即使比较的是同一个不可达块也返回 false。此约定避免后续 pass 误用未分析区域。

mem2reg 的重命名按支配树遍历，而不是按 CFG DFS 遍历。进入块时压入 PHI 结果及后续 store 产生的定义，离开块时恢复对应 slot 的值栈。

## 5. 支配边界

B 属于 A 的支配边界，当且仅当 A 支配 B 的至少一个可达前驱，但 A 不严格支配 B。

第一版采用前驱向上行走算法：

```text
for 每个具有至少两个不同可达前驱的块 B:
    for B 的每个可达前驱 P:
        runner = P
        while runner != idom(B):
            将 B 加入 frontier(runner)
            runner = idom(runner)
```

构造期间向边界列表追加，结束后按块索引排序并去重，保证查询结果稳定。入口无前驱的约束保证这段过程不会因为入口回边而无法终止。

循环头可以出现在自己的支配边界中，这是正常结果，不能删除。例如循环头 H 有入口边和循环回边时，H 可能属于 `frontier(H)`。

### 5.1 与 PHI 放置的关系

mem2reg 对每个可提升 slot 收集所有定义块，计算这些块的迭代支配边界 IDF：

1. 将定义块放入工作队列。
2. 弹出块 X，遍历 `frontier(X)`。
3. 尚未为该 slot 放置 PHI 的边界块 Y，放置 PHI。
4. 新放置的 PHI 也是一个定义；若 Y 尚未处理，将其加入工作队列。
5. 重复直到队列为空。

DF 是单个块的边界，IDF 是反复传播得到的闭包，两者不能混淆。第一版可以采用未剪枝的 PHI 放置；以后结合 slot 活跃性生成 pruned SSA，减少无用 PHI。

`Undefined` 输入在重命名时根据各前驱出口处的当前定义填入，不由支配边界分析推断。

## 6. 示例

菱形 CFG：

```text
    entry
    /   \
  left  right
    \   /
     merge
```

结果：

```text
idom(left)  = entry
idom(right) = entry
idom(merge) = entry

children(entry) = [left, right, merge]
frontier(left)  = [merge]
frontier(right) = [merge]
```

如果同一个 slot 分别在 left、right 定义，mem2reg 在 merge 插入 PHI。

循环 CFG：

```text
entry -> header -> body -> header
             \-> exit
```

结果：

```text
idom(header) = entry
idom(body)   = header
idom(exit)   = header

frontier(body)   = [header]
frontier(header) = [header]
```

## 7. 失效规则

以下修改后必须重建 CFG 和支配分析：增加或删除基本块、改变块索引顺序、修改入口、增加或删除控制流边、改变跳转目标。当前不自动侦测修改，由调用方负责失效管理。

仅增加 PHI、替换普通操作数、删除 load/store 而不改变控制流时，不影响支配关系。分析绑定阶段版本，不使用全局世界计数失效，不跨 Non-SSA、SSA 和优化版本混用。

复制阶段版本时，必须为目标版本重新建立块指针关系和分析，不能沿用源版本的指针结果。
